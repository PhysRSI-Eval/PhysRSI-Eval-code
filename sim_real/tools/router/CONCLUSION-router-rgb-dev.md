# ROUTER-RGB 开发结论（能力线 Track D，2026-10-30；开发级，不是预登记判定）

## 1. 已见任务上的 router（基准任务集固定，6 个 C1 任务都可以训练）
数据来自 rsiws-dc 的 E1（ee-physword out/router-dev-{rgb,prop}-f*.json），取 TEST 划分，5 折平均：

| 输入 | auroc_c1 | auroc_route | 路由召回（p≥0.5） | 误路由 |
|---|---|---|---|---|
| 只用 RGB | 1.00 | 0.992 | 0.885 | 0.020 |
| RGB + 本体 | 1.00 | 0.992 | 0.872 | 0.020 |

第 (b) 级（插充电器是否接手，不给任务 id 和工具事实）：router 成功率 0.254，等于上限；总交给 Astra 0.075，总用 rg3f 0.209，有害 0 次（DEV-b-*.json）。
→ 对于已见过的任务，可以只凭 RGB（加本体）完成路由。

## 2. 推广到没见过的任务：FAIL
每一折整任务留出 1 个 C1 任务和 1 个非 C1 任务。C1 任务每次只留出一个，从来没有同时留出多个。

| 留出的 C1 任务 | 路由召回 | auroc_route | 同折留出的非 C1 任务 | 该任务的误路由 |
|---|---|---|---|---|
| deposit_coin | 0.135 | 0.62 | build_tower | 0.182 |
| fill_pen_holder | 0.015 | 0.65 | fold_clothes | 0.031 |
| insert_key | 0.318 | 0.84 | imitate_sorting_sequence | 0.186 |
| insert_tubes | 0.0（只有 46 个路由正例） | 0.95 | pack_objects_into_box | 0.077 |
| plug_in_charger | 0.541 | 0.92 | play_Xylophone | 0.429 |

留出部分上"C1 对非 C1"的 AUROC 只有 0.10–0.57。读法：已见任务上接近完美，是因为模型认出了训练过的任务，学到的不是"精密插入"这一类。
ROUTER-RGB-v2 的开发实验正在测类别层面的线索：夹爪附近的局部 token、"握着的物体靠近另一个物体"的几何线索、本体的阶段特征。

## 3. 方法适配（用户 08:3xZ）
- **E1 的定位**：适用于固定的基准任务集，因为 6 个 C1 任务都可以训练。它不算失败；它的适用范围就是"已见任务"。
- **ROUTER-RGB-v2 开发**（v2/RESULT-v2-dev.json；留一 C1 任务，每格为留出 C1 任务的召回 / 同折留出非 C1 任务的误路由）：

| 变体 | deposit_coin | fill_pen_holder | insert_key | insert_tubes | plug_in_charger |
|---|---|---|---|---|---|
| 基线（全局 token） | 0.14 / 0.03 | 0.10 / 0.08 | 0.37 / 0.01 | 0.63 / 0.21 | 0.40 / 0.43 |
| (i) 夹爪局部 | 0.21 / 0.04 | 0.04 / 0.05 | 0.44 / 0.02 | 0.67 / 0.27 | 0.56 / 0.45 |
| (ii) 基线 + 几何 | 0.23 / 0.06 | 0.11 / 0.09 | 0.40 / 0.01 | 0.44 / 0.21 | 0.50 / 0.35 |
| (iii) 基线 + 阶段 | 0.25 / 0.12 | 0.18 / 0.07 | **0.70 / 0.04** | 0.83 / 0.28 | 0.40 / 0.37 |
| 只用几何 + 阶段 | 0.64 / 0.21 | 0.22 / 0.10 | 0.62 / 0.03 | 0.67 / 0.22 | 0.48 / 0.26 |

- **按任务看哪组特征有用**：
  - insert_key：本体阶段特征有用（0.70 / 0.04，达到召回 ≥0.5 且误路由 ≤10% 的门槛）。
  - deposit_coin：类别线索（几何 + 阶段）把召回提到 0.64，但误路由 0.21（build_tower 里也有"握着东西靠近别的东西"）。
  - plug_in_charger：夹爪局部 token 有用（0.56），但被 play_Xylophone 混淆（握着木槌靠近琴键），误路由 0.35–0.45。
  - insert_tubes：路由正例只有 46 个，误路由来自 pack_objects_into_box。
  - fill_pen_holder：没有一组特征有用。
- **归因**：类别线索本身能推广（insert_key 达标，coin 和插充电器的召回上升），但"握着东西靠近另一个物体"在非 C1 任务里也常见，误路由因此偏高。
  - 方法上，需要能区分"插入"和"敲击、放置"的线索，例如接触前的对准姿态、目标上的孔或槽；
  - 数据上，只有 5 个 C1 任务，太少。
- **router 的真正目标是方法适配表**（fitmap/FITMAP.md）：每个状态应交给在那里有用的方法。
  - v0 由 84 个唯一的插充电器状态构成，其中 11 个有 VS 结果。
  - 接手早（t ≤100）且 v4 正常：rg3f 15 个，VS 2 个，Astra 1 个，都不成功 30 个。
  - 抬起时 v4 弃权：所有方法都不成功（0/20）。
  - 接手晚（t >100）：VS 1 个，Astra 3 个。

## 4. ROUTER-RGB-v3 开发：加入"握持物与 CAD 模板匹配"线索（v3/RESULT-v3-dev.json）
做法：把 12 个物体 CAD 的点云渲染成模板图（可插入的物体 5 个，含近似的硬币和笔；不可插入的 7 个），用 DINOv3 编码，再算它们和夹爪局部 token 的余弦相似度。
表中每格为留出 C1 任务的召回 / 同折留出非 C1 任务的误路由。

| 变体 | deposit_coin | fill_pen_holder | insert_key | insert_tubes | plug_in_charger |
|---|---|---|---|---|---|
| v2 基线 + 阶段 | 0.25 / 0.12 | 0.18 / 0.07 | 0.70 / 0.04 | 0.83 / 0.28 | 0.40 / 0.37 |
| 基线 + 阶段 + CAD | 0.29 / 0.15 | 0.16 / 0.06 | 0.52 / 0.02 | 0.78 / 0.24 | 0.33 / 0.35 |
| 阶段 + CAD | 0.51 / 0.27 | 0.18 / 0.06 | 0.60 / 0.10 | 0.72 / 0.32 | 0.60 / 0.42 |
| 只用 CAD | 0.45 / 0.22 | 0.10 / 0.06 | 0.49 / 0.21 | 0.26 / 0.44 | **0.51 / 0.17** |

按任务看：
- 插充电器 ↔ 木琴：只用 CAD 线索时，误路由从 0.37–0.45 降到 0.17，召回 0.51。CAD 匹配确实能把充电器和木槌分开。
  但和全局 token 或阶段特征放在一起时，这个效果被淹没了。
- 硬币 ↔ build_tower：CAD 线索没有降低误路由（0.22–0.31）。点云渲染的薄圆盘和积木在 DINOv3 里分不开。
- insert_key：最好的仍然是 v2 的"基线 + 阶段"（0.70 / 0.04）。

归因：方法。点云渲染模板对形状差别大的物体有用（充电器对木槌）；对薄而小的物体没用（硬币），那里需要真实外观或网格渲染。
下一步：把 CAD 线索做成门控的第二路分支（例如只在阶段特征显示"已握住并接近"时才看 CAD 匹配），不要和其他特征直接拼接。

## 5. v3g 开发：门控的 CAD 分支（v3/RESULT-v3g-dev.json）
规则：阶段分支判为路由，并且 CAD 分支（只在"已握住"的样本上训练）也判为路由，才路由。
表中每格为留出 C1 任务的召回 / 同折留出非 C1 任务的误路由。

| 门控 | deposit_coin | fill_pen_holder | insert_key | insert_tubes | plug_in_charger |
|---|---|---|---|---|---|
| 阶段 → CAD | 0.43 / 0.16 | 0.06 / 0.06 | 0.32 / 0.07 | 0.91 / 0.22 | 0.38 / 0.40 |
| 基线 + 阶段 → CAD | 0.23 / 0.10 | 0.06 / 0.03 | 0.38 / 0.04 | 0.78 / 0.18 | 0.19 / 0.29 |

读法：
- 门控没有复现"只用 CAD"时插充电器对木琴的分离效果（那时是 0.51 / 0.17）。
- 只在"已握住"样本上训练的 CAD 分支，没学到能推广到没见过的任务的区分。
- 召回下降，误路由基本不变。
- 归因：方法（训练数据子集太窄）+ 数据（只有 5 个 C1 任务）。

结论：在没见过的任务上，只有 insert_key 一项达标（v2"基线 + 阶段"）。插充电器对木琴的混淆，只有在单独使用 CAD 线索时有所缓解。
coin 沿用已见任务上的 E1。暂停，等 C1 线的真值上限标签。
