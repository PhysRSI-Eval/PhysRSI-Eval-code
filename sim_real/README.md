# sim_real：harness v2 与工具链（仿真结论 + 可复用代码，供真机线与仿真线同步开发）

分支 `harness-v2-sim-real-20261030`，基于 `main`（PhysRSI-Eval 参考基础设施）。只放代码和小配置（约 1.5 MB）；数据、特征、模型权重都在共享盘 `/lizekai/RSIws`（真机主机与仿真集群共用），下文给出路径。
所有结论截至 2026-10-30，全部来自仿真（RoboDojo），零额度离线实验为主；"判定"指预登记后只判一次的结果，"开发级"指没有预登记的探索结果。

## 1. 相对旧流线改了什么

| | 旧流线（main 分支，论文实验） | 当前（本分支） |
|---|---|---|
| 策略 | Astra 作为 VLM 策略，K 轮 RSI 自行迭代 skill，技能库从空开始 | 底座不变；在外面加工具、事实与路由，Astra 仍是主策略 |
| 工具 | 只有原生动作接口 | **L1 工具注册表**：统一返回 `{value, uncertainty, abstain, steps_used, note}`，带契约检查，违约结果不交给模型 |
| 信息 | 只有图像与原生反馈 | **L2 状态块**：只给事实（不给建议），按决策点送达 |
| 介入 | 无 | **L3**：工具结果只回复给模型自己的调用；执行器只在显式调用或路由器判定时运行；条件介入门控 / 路由器（只在"介入比 Astra 自己做更好"的状态介入） |
| 经验 | 每条链各自的 workspace | **L4 经验包**（RoboSkill 式 rsi-exp-v1），跨任务共享 workspace，只放可重算的 binding，不放场景坐标 |
| 感知 | 无 | 每任务 KPNet 功能关键点（CAD 自动标注）+ 多视角三角化；DINOv3 小物体分割；RGB 任务 / 阶段识别 |
| 执行 | Astra 自己出动作 | 插入类的**相对视觉伺服执行器**（被插件与目标在同一组图里三角化，直接伺服相对误差） |

代码：`harness_v2/rsi_v2/`（L1–L4、门控与路由接口），`harness_v2/release/`（hv2e / hv2f 构建与离线测试），说明见 `harness_v2/READY.md`。

## 2. 当前思路（为什么这样做）

1. **先分类再攻关**。42 个 RoboDojo 任务 = 通用技能（接近、抓、抬、移动、旋转、放、交接、按钮、复位）+ 7 类专属技能：A 精密插入（10 个）、B 倾倒（3）、C 工具使用（3）、D 推动（1）、E 抓放排序（17）、F 记忆 / 时序 / 动态（7）、G 可形变（1）。每类用一套可复用方法，至少在该类的 2 个任务上验证。
2. **每个难点先判断是工具问题还是 harness 问题**。插入类（主攻）的普查（878 个 Astra 回合，仿真真值）给出三个共同难点：
   - 搬运中掉落 / 在手滑动（各任务 19–45% 掉落；插头搬运中滑动约 15 mm）——工具（握法、握持检查）+ harness（发现与恢复）；
   - 到达悬停位与对准（插头、钥匙各丢约一半）——工具（可达性含**自碰撞**、重抓、相对伺服）；
   - 对准后插不进 / 做不完（硬币 51%、笔筒 18%、钥匙 0%）——工具（插入策略）+ harness（多物体进度、步数）。
3. **路由器是系统核心**：第 0 层只凭 RGB 认任务 → 第 1 层认阶段（粗阶段 DINOv3，细阶段用关键点相对误差）→ 第 2 层查"任务 × 阶段 → 工具"表；是否接管由"介入是否优于 Astra 自己做"的配对数据决定。
4. **按"在哪里有提升"评价方法**，不只看总分：一个方法总分没过，往往是用错了任务或状态；适配图本身就是路由器的训练数据。

## 4. 不可行或被证据否定的路径（不要重复）

"一定不可行"只用于物理或评测器层面的结论；其余是"在当前设置下被否定"。

| 路径 | 结论 | 原因 |
|---|---|---|
| swap_blocks、store_laptop_and_headphones 的仿真成功 | **一定不可行（仿真评测器缺陷）** | swap_blocks 按钮复位后静止比例 0.75–0.8 低于计数阈值 0.95（167 回合 0 成功）；store_laptop 的 bottom 点要低于桌面 3.5 cm，几何不可满足。真机不受影响 |
| 细把手工具（锤、扳手）靠当前夹爪夹持搬运 | **物理上不可行（当前夹爪）** | 夹紧裕度 1.9–7.4 对需要的 18–50（0/55）。真机换夹爪或抓法族才有可能 |
| 把建议写成文字给模型、指望它照做 | 否定 | 信息正确但 Astra 0 次调用；文字建议 4/4 不执行 → 精细动作改为工具执行的宏动作 |
| 一律由执行器接管 | 否定 | 同批 48 个 Astra 状态：接管 1/48，Astra 自己 24/48 → 只做条件介入 |
| 倾倒用执行器接管 | 否定 | 在 Astra 成功回合上接管反而 4/9–5/9 才成功（抬升滴洒）→ 倾倒只给落点偏移事实 |
| SAM3 做小 / 薄物体 | 否定 | 硬币帧检出 14–22%；改 DINOv3 |
| 只用 RGB 的 CAD 轮廓渲染对比做分割 / 位姿 | 否定（无先验时） | 单轮廓位姿歧义；需桌面平面、FK 或双视角约束 |
| 绝对定位链（locate_mm + 在手位姿 + FK 算目标手姿）后直接插 | 否定（第 2 关 0/42） | 误差叠加；改**相对**伺服（被插件与目标同框） |
| 单视角在手位姿用于扁平物体 | 否定 | 正反面 180° 歧义（充电器拟合转角中位 178°）；多视角 / 时序延续 / 相对伺服绕开 |
| 只靠持握腕部 + 头部相机三角化插头 | 否定 | 视角之间物体在动（14–22 mm）；需同时拍摄或空闲臂无碰撞视角 |
| 时序跟踪（手中转动时） | 否定 | 跟踪漂移，逐帧检测更好 |
| PhysWord 式动词锚定（动作 → 视频对齐） | 否定（无增益） | 3 个种子 WO 都略低于 O；动词标签只保留作辅助 |
| 用 RGB 识别"未见任务"属于哪一类 | 否定（当前数据） | 留一任务召回 0–0.54：模型记住场景而非类别；部署在固定任务集上不需要 |
| 预测松手后的落点（cm 级回归） | 否定 | 钥匙落点所有方法 4.6–5.3 cm；改为"是否落在功能区域"的分类与防掉 |
| 在旧回合 DEV 上校准路由阈值 | 否定 | DEV 负样本太容易，阈值失真（误路由 0.31–0.43）；要在留出布局等"像新数据"的集合上校准 |

## 6. 真机开发指引（建议）

1. **先移植"感知 → 相对伺服"这一条最强的链**（插入类）：
   - 关键点定义直接复用 CAD 功能点表（`tools/kpnet/`、finepose README §2）；
   - **标签**：仿真用真值位姿投影；真机没有真值，可用（a）AprilTag / 动捕 / 手眼标定后的 CAD 配准自动标注，（b）仿真预训练 + 少量真机标注微调；
   - **三角化**需要空闲臂视角或第二相机，且**同时拍摄**（仿真里两视角之间物体移动造成 14–22 mm 误差）；
   - 相对误差在同一组图里计算，标定误差大部分抵消，这是真机最友好的部分。
2. **可达性先做自碰撞**：换成真机 URDF 和碰撞模型（`self_coll.py` 的接口不变）。
3. **路由器**：任务识别在真机上要重新采集画面（仿真画面不能直接迁移）；阶段识别建议直接用关键点相对误差做细阶段，不依赖全局特征。
4. **握持与掉落**：真机有力 / 触觉信号时，优先用它们做握持检查；仿真里 DINOv3 视觉检查与真值一致 29/29，可作为无力传感时的后备。
5. **不要移植的**：倾倒执行器接管、文字建议、一律接管（见 §4）。

## 7. 两条线同步开发（建议）

- **分工**：仿真线负责方法验证与适配图（哪种方法适合哪类任务 / 状态）；真机线负责同一方法在真机上的感知数据与执行接口。
- **共享接口**（两边保持一致）：
  - 工具返回格式 `{value, uncertainty, abstain, steps_used, note}`（`rsi_v2/contract.py`）；
  - 关键点表（CAD 功能点名称与坐标系）与 `kp_api` 的 detect / triangulate / relative；
  - 执行接口 `move / move_to / target_hand / grip`（`fp_lib.Env`）；
  - 路由器输入（三路 RGB + 本体）与输出（任务、阶段、工具）。
- **共享盘约定**：真机数据放 `/lizekai/RSIws/real/<任务>/<日期>/`，与仿真同样的 frames / arrays / truth 布局（见 `tools/alignment/export_astra_v1.py` 的格式说明），这样同一套训练脚本两边都能读。
- **仓库只放代码与小配置**；数据、特征、权重放共享盘，在 README 里写路径与 sha256。

## 9. 后续开发建议

1. 插入类：修 D4（重抓后的可达性加入自碰撞检查）→ 视角（空闲臂无碰撞视角 / 头相机兜底）→ D6 插入策略（守护插入 + 小范围螺旋搜索）；然后把真值关键点换成 KPNet，量化感知差距。
2. 第二个插入实例（钥匙）用同一个执行器，验证"只换物体描述 + 重训关键点"的可推广性；之后试管、硬币投币缝。
3. 路由器：任务识别已可用；阶段识别的细阶段改用关键点相对误差；介入判定（第 2 层）在每个新实例上重拟合。
4. 搬运滑动：在悬停位插入前重新测量被插件（相对伺服可以吸收滑动），并接入滑脱预警。
5. 真机：先在一台机器上跑通"关键点 → 相对伺服 → 守护插入"单任务闭环（插头或钥匙），再接路由器。
