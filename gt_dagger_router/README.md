# RSIws 当前迭代说明（2026-10-31，rsiws-32）

范围：RoboDojo 中 Astra 最弱的插入类（K1）任务。部署时只能用 RGB、本体感觉和任务指令；仿真真值只用于生成训练标签、充当专家，以及作对照上限。

## 1. 迭代思路
1. **先分类**：把 42 个任务拆成"共享技能"和"类别技能"两层。共享技能有定位、移动、旋转、抓取、抬起搬运、放置、阶段判断；类别技能有插入、特殊抓取、倾倒、堆叠、按压敲击、推、逻辑记忆、铰接柔性、动态。见 `reports/progress/TASK-SKILL-TAXONOMY-20261030.md`。
2. **路由器是 harness 的核心**：认出是哪个任务 → 判断处在哪个阶段 → 查表决定由 Astra 继续，还是交给某个工具或执行器。
3. **工具分两类**：感知类给出毫米级的测量（关键点、插孔、在手位姿）；操作类直接驱动手臂完成一段动作。
4. **训练方式**：先用 teacher forcing 在正确轨迹上学（官方 GT 示教 9 任务 × 100 条），再在仿真里在线 rollout，由掌握真值的专家纠正失败状态，循环迭代（DAgger）。
   - 从 10-31 起，"正确轨迹"增加了真值专家从 Astra 交接状态出发录下的示范。原因是官方示教都从开局用标准握法开始，迁移不到 Astra 已经握住的状态上。
5. **执行方式**：实验一律通过 tmux 队列脚本（`ops/jobq`）运行，子代理只读结果、排下一轮。进度看 `reports/progress/DASHBOARD.md`。

- 插充电器有三项检查。
- 原生步数上限以内完成，记为 native_success；放宽上限后才完成，另记为 timeout_success。下文除特别说明外，都指 native_success。

**"交接状态"有两层意思**：
- **控制权交接**：Astra 先操作，握住插头并抬起约 4.5 cm 后，把控制权交给工具。插充电器的 83 个唯一起点就是这样得到的。

## 4. 阶段检测能精细到什么程度
- **粒度**：逐帧判断属于 5–6 个共享阶段中的哪一个：接近、抓取-抬起、搬运、对准或执行、已插好或已放好（以及松手）。"执行"按类别定义：插入是靠近目标并握着，倾倒是倾斜超过 45°，推是贴近桌面并平移。
- **精度**：插入类阶段准确率 0.86–0.90；"抓取-抬起"F1 0.82，容许切换点前后差 5 步时 0.90；"已插好"F1 0.39 / 0.79（验证 / 测试）。9 个官方任务里，插入 0.99、敲击 0.97、长时序 0.90、推 0.82–0.87。
- **做不到的**：
  - 毫米级状态，比如钥匙尖离锁孔几毫米、是否已经接触；
  - 物体在手里是否在滑动；
  - 双手交接中的子阶段，比如接收手是否已经夹住。
- 掉落风险提前预警目前不可用：误报 10% 时，52 次掉落只抓到 1–9 次。

## 5. 抓钥匙长柄、双手交接和夹爪碰撞
**现状**：这一段目前没有专门的工具，也没有成功的例子。
- host3 的前半程（从桌上抓钥匙 + 双手交接），各版本合计交接 0/12。
- 我们这边用脚本从桌上抓钥匙：捏柄端时钥匙在转成竖直的过程中掉落；改捏质心并放慢旋转，同样失败。
- C2 的空中交接（扳手）没有夹住。瓶子在交接位姿上转角差 8–13°，容差只有 7°。

**夹爪碰撞现在怎么避免**：基本没有避免。
- 部署 harness 的 check_reach 只做逆运动学，不检查碰撞。
- C1 执行器的 cuRobo 检查只覆盖单臂自身各节之间的碰撞，以及桌面、插座这些场景物体，不包括两只手之间、夹爪对夹爪、夹爪对被递物体的碰撞。
- 所以双手交接时发生的碰撞，目前不在任何检查之内。

**建议的解法**（都要新增"操作类"工具，并用官方 GT 学"正确的姿势"）：
1. **从官方示教里提取正确的抓取和交接姿态**：官方 insert_key 有 100 条完整示教，包含抓长柄和双手交接。用本体感觉切出"抓取时刻"和"交接时刻"（两只手同时闭合的那几帧），把两只手的末端位姿换算到钥匙坐标系（由关键点或 CAD 得到），聚类成几个模板。部署时只用 RGB 定位钥匙，再套用模板。
2. **grasp_long_handle 工具（操作类）**：用模板和 CAD 抓法合成生成候选抓取（柄中心、接近方向垂直于柄、靠近重心）。用 cuRobo 做可达性和碰撞检查，执行后用 check_held 确认是否握住。
3. **bimanual_handover 工具（操作类）**：
   - 递出手先移到模板交接位姿；
   - 接收手沿柄轴方向接近；
   - 碰撞模型同时放入两条手臂、两只夹爪（按实际开合建模）和被递物体，要求最小间隙不小于设定值；
   - 交接顺序：接收手先闭合，确认握住后，递出手再张开。
4. **teacher forcing 学交接段**：只用官方示教里的交接片段训练一个"交接技能"动作块策略。在线 rollout 后，由第 3 点的规划器充当专家纠正（DAgger）。
5. **路由器配合**：在阶段里加入"交接中"（两只夹爪同时闭合）。只有在这个阶段才调用交接工具，交接完成后再交给插入工具。
